# auto-issue 스킬 작동 가이드
사용자가 `/auto-issue` 명령을 전송했을 때 에이전트는 아래 절차에 따라 작업을 수행합니다.

## 0단계. 호출 방식 판별 및 신규 이슈 생성
- 사용자가 `/auto-issue <작업 내용>`과 같이 뒤에 추가적인 작업 명칭을 덧붙여서 호출한 경우:
  - 에이전트는 입력된 `<작업 내용>`을 제목으로 하여 새로운 GitHub 이슈를 생성합니다.
    `gh issue create --title "<작업 내용>" --body "자동 생성된 이슈"`
  - 이슈가 정상적으로 생성되면 사용자에게 생성된 이슈 번호와 정보를 전달하고, **대기 상태**에 들어갑니다.
  - 사용자가 **"작업 진행해줘" 또는 "시작해줘" 등 진행을 직접 지시하기 전까지는 절대 후속 단계를 자동 수행하지 않고 대기**합니다.
  - 사용자가 진행을 지시하면 새로 생성된 이슈 번호를 기준으로 하여 2단계(작업 브랜치 생성)부터 과정을 이어 나갑니다.
- 사용자가 `/auto-issue` 단독으로 호출한 경우:
  - 1단계(오픈 이슈 조회 및 선택)부터 동작을 수행합니다.

## 1단계. 오픈 이슈 조회 및 선택
- 에이전트는 GitHub CLI를 사용하여 현재 오픈 상태인 이슈 목록을 조회합니다.
  `gh issue list --state open`
- 조회된 이슈 목록을 사용자에게 명확히 전달하고, 어떤 이슈 번호에 대해 작업을 진행할지 입력을 요청합니다.

## 2단계. 작업 브랜치 생성
- 선택된 이슈 번호와 이슈 제목의 핵심 키워드를 조합하여 `issue-번호-키워드` 형식의 브랜치 이름을 결정합니다.
  예: 이슈 번호 1번, 제목 "Git에 대한 설명 추가하기"인 경우 브랜치명은 `issue-1-git`이 됩니다.
- 기본 브랜치(main 또는 master)로 이동하여 최신 상태를 반영한 뒤, 결정한 브랜치명으로 새 브랜치를 생성하고 체크아웃합니다.
  `git checkout -b issue-번호-키워드`

## 3단계. 파일 수정 및 변경 사항 확인
- 이슈 본문에 작성된 요구사항을 바탕으로 필요한 파일 수정을 진행합니다.
- 작업 완료 후 `git status` 및 `git diff`를 통해 변경 사항이 정확히 반영되었는지 확인합니다.
- 변경된 파일들을 스테이징 영역에 추가합니다.
  `git add <수정된 파일 경로>`

## 4단계. 커밋 메시지 생성 및 커밋 실행
- commit 스킬의 규칙에 맞추어 커밋 메시지를 생성합니다.
- **제목(첫째 줄)**: 변경 사항을 명확히 설명하는 1문장 요약 (이슈 번호 명시)
- **공백(둘째 줄)**: 비어 있는 행
- **본문(셋째 줄 이후)**: 수정 목적 및 구체적인 수정 내용 상세 설명
- **끝맺음(본문 마지막)**: 본문 맨 마지막 부분에 반드시 "화이팅"을 포함
- 생성된 커밋 메시지를 사용자에게 보여주고 커밋 진행 여부(`y/n`)를 확인받습니다.
- 승인 완료 시 Git 커밋을 실행합니다.

## 5단계. 브랜치 병합
- 기본 브랜치(main 또는 master)로 체크아웃합니다.
  `git checkout main` (또는 master)
- 생성하여 작업했던 이슈 브랜치를 기본 브랜치에 병합합니다.
  `git merge issue-번호-키워드`

## 6단계. 이슈 댓글 등록 및 완료 처리
- 이슈의 댓글로 작업 완료 내역을 상세히 작성합니다. 이때 작업자는 Naming Convention에 따라 `Chu Yumin`으로 기재합니다.
  `gh issue comment <이슈 번호> -b "<작업 상세 설명>"`
- 해당 이슈의 해결이 완료되었으므로 이슈를 닫아 완료 상태로 표시합니다.
  `gh issue close <이슈 번호>`
